## index.ts (types)

**Purpose:** Canonical home for shared domain types. Re-exports Drizzle-inferred row types for the `universe_*` and `ap_*` tables.
**File:** `src/types/index.ts`

For each table `X` exports `X` (`InferSelectModel`) and `NewX` (`InferInsertModel`), e.g. `UniverseSystem` / `NewUniverseSystem`. Import row types from here, never re-infer inline.

Re-exports realtime wire-contract types and ESI opKey types.

Re-exports the ESI decoded-response types.

Re-exports `RealtimeStatus`.

Re-exports map-event payloads, mutation result/input types, signature parser/resolver types, `ParsedDscanRow` (the D-Scan paste parser row, `src/lib/map/dscanParser.ts`), `ScanTypeRow` (the SDE verdict on one scanned type id, `src/lib/eve/shipTypes.ts`), and wormhole-catalog lookup results.

Re-exports `UniverseSovereigntyMap` / `UniverseFactionWarSystem`, ESI sov/FW decoded-response types, and read-side integration summaries (`SystemIntelSummary`, `SovereigntyIntel`, `FactionWarIntel`, `RecentKillSummary`, `EveScoutConnectionSummary`, `ChangelogRelease`). Also re-exports `SystemStatsSummary` (rolling 24h activity totals, `src/lib/map/stats.ts`).

Re-exports `SignatureGroupKey` (the `signature_group_key` pgEnum) and `SignatureGroupOption` for the scanner-level signature group catalog. The corresponding column on `ap_map_signature` is `groupKey: SignatureGroupKey | null` (replacing the prior `groupId` FK to `universe_group`). `CosmicSignatureGroupKey = Exclude<SignatureGroupKey, 'wormhole'>` is the union of the six non-wormhole groups whose site names live in the static catalog `src/lib/map/signatureSites.ts`. Also re-exports `SignatureClassKind` / `SignatureClassOption` for the localized scanner Class-column catalog (`src/lib/map/signatureClasses.ts`), and `SignatureActivity` (`'combat' | 'exploration'`) for the site-safety axis (`src/lib/map/siteActivity.ts`), orthogonal to `SignatureGroupKey`.

Re-exports the static-reference dialog types: `SystemEffect` / `SystemEffectBonus` / `SystemEffectKey` (`src/lib/eve/systemEffects.ts`) and `WormholeJumpInfoRow` (`src/lib/eve/wormholeJumpInfo.ts`).

Re-exports the sound-cue types from `src/lib/sounds/prefs.ts`: `SoundEvent` (the closed cue vocabulary `pilotArrived`/`pilotLeft`/`watchedJump`/`killInSystem`/`rallySet`/`systemPinged`), `SoundId` (a chime id, a `voice-<pack>-<event>` id or `custom:<uuid>`), `SoundPrefs` (the account-level blob on `ap_user.sound_prefs`), `SoundMuteGroup` (`'kills' | 'pilots' | 'alerts'`), `SoundMutes` (one flag per mute group), `SystemSoundMute` (a per-system mute entry keyed by EVE system id, with its display name), `SoundCueSystem` (`{ systemId, isHome }`, the system a cue happened in), `SoundVariant` (`'plain' | 'inbound' | 'outbound'`, the viewer's side of a watched wormhole) and `VoicePackId` (`'ada' | 'cowboy' | 'malyx'`).

Re-exports `ApStructure` / `ApStructureEvent` row types, `StructureEventKind` (the `structure_event_kind` pgEnum), `IntelScope` (the `intel_scope` pgEnum — `'private' | 'corp' | 'alliance'`, the tenancy of a manual-intel row), the read-side view-models `StructureIntel` / `UpwellStructureType` (`src/lib/structures/read.ts`), the structure mutation input types, the structure client body shapes (`CreateStructureBody` / `UpdateStructureBody`), and `FetchResult` (the shared no-`eventId` JSON result from `src/lib/http/fetchJson.ts`).

The "add system manually" flow re-exports `SystemSearchResult` (`src/lib/map/systemSearch.ts`) — a solar-system search row used by `AddSystemDialog`.

The structure owner picker re-exports `CorpSearchResult` (`src/lib/structures/corpSearch.ts`) — `{ id, name }` corporation matches for the `StructureFormDialog` autocomplete.

Defines `UnderglowConfig` (directly defined, not a re-export) — the color/brightness/duration/speed knobs for the versatile map-node underglow (`src/components/map/SystemUnderglow.tsx`), keyed per notification kind in `underglowPresets.ts`.

Re-exports `TagScheme` (the `tag_scheme` pgEnum union: `none`/`abc`/`0121`) and the auto-tagging strategy contract from `src/lib/tagging/types.ts`: `ActiveScheme`, `TagSystem`, `TagEdge`, `TagContext`, `TagStrategy`, `AvailableTags`. `MapSettings` + `MapViewData.map` gain `tagScheme` + `homeMapSystemId`.

`MapContextMenuTarget` (directly defined) — the right-click target on the map canvas: a discriminated union over `system`/`connection`/`connectionEnd`/`note`/`pane` carrying the row `id` (except `pane`) plus the cursor's client `x`/`y` for anchoring the menu; `connectionEnd` additionally carries `end: ConnectionEnd` naming which mouth was clicked. `null` ⇒ no menu open. Consumed by `MapContextMenu` (`src/components/map/MapContextMenu.tsx`) and driven by `MapCanvas`'s xyflow context-menu handlers.

`ConnectionEnd` (directly defined) — `'source' | 'target'`, which mouth of a connection an operation refers to. Used by `ConnectionEdge`/`ConnectionEndpoint`'s endpoint context-menu callback.

Re-exports the Thera module types from `src/lib/map/thera.ts`: `TheraHub` (`'Thera' | 'Turnur'`), `TheraConnection` (oriented + class-enriched EVE-Scout row), `TheraSyncInput`, and `TheraSyncResult` (`{ summary, payloads }`).

Re-exports `ApMapConnectionLog` / `NewApMapConnectionLog` (the `ap_map_connection_log` row) and the `ConnectionMassLogEntry` view type — a display row for the per-jump connection mass-log (joined character + ship-type name, `mass`/`cumulativeMass` as `number` kg). `MapConnectionMassLogEntry` (directly defined) is the same row plus its `connectionId`, from a map-wide listing. See `src/lib/map/connectionMassLog.ts`.

`ShipClass` (directly defined) — the broad hull-class bucket for a ship type (`'frigate' | 'cruiser' | 'dreadnought' | ...`, 18 values), resolved server-side from `universe_type`'s SDE group by `resolveShipClass` (`src/lib/eve/shipClass.ts`). Feeds `ShipClassIcon` (`src/components/icons/ShipClassIcon.tsx`) and rides on `MapPresenceEntry.shipClass`.

The delete-subchain feature re-exports `DeleteSubchainInput`, `SubchainDeleteSummary`, and `SubchainDeleteResult` (`{ summary, payloads }`) from `src/lib/map/mutations/subchain.ts` — an N-event branch teardown matching the bulk-paste/Thera `{ summary, payloads }` shape. The Stage 4 sig-memory restore re-exports `RestoreConnectionInput` and `RestoreConnectionResult` (`{ payloads }`) from `src/lib/map/mutations/restoreConnection.ts` — an N-event re-confirm (`system.added` per hidden endpoint, then `connection.create`).

Permissions-overhaul adds `ApInstance` / `ApInstanceOwner` / `ApAccessGrant` row types (`+ New*`) and the enum unions `AccessMode`, `AccessPrincipal`, `AccessScope`, `AccessCapability` (from `src/db/schema/ap/enums.ts`).

Blackout types (directly defined): `BlackoutState` (`{ active, since, byCharacterId }` — the instance-wide switch on `ap_instance`) and `BlackoutViewer` (`{ active, cleared, userId }` — one viewer's standing, the input to the `isBlackedOut` / `isPilotHidden` predicates). Produced and consumed by `src/lib/auth/blackout.ts`. Re-exports `BlackoutStatus` (`{ active, since, cleared }`, `since` an ISO string — one socket's standing as `healthCheck` carries it, `src/lib/realtime/protocol.ts`). The admin panel's view-models: `BlackoutClearance` (one `blackout_view` grant with its resolved character name or title label, a title's corp, expiry, an `expired` flag and note), `BlackoutTitleOption` (a `corp_title` role the cleared list can name) and `BlackoutPanelData` (switch state with who turned it on, the cleared list, and the character / title picker options; ids and dates as strings). Produced by `src/app/(admin)/actions/blackout.ts`.

User API types (directly defined): `UserApiErrorCode` (the stable `code` strings of `/api/v1/*` refusals), `UserApiTokenRecord` (a token resolved with its map's API state, its owning account's block columns and main, and `access`: the main's `canViewMap` and login-gate results plus the account's `BlackoutViewer`, null when the token was already dead at resolve time) and `UserApiDecision` (allow with the record, or a 401 / 403 refusal with its code, a `retryAfterSec` on a suspension, and the record on 403s only). Produced and consumed by `src/lib/userApi/authorize.ts`. `UserApiIpGateDecision` (allow, or a refusal with `retryAfterSec`) and `UserApiRateDecision` (allow with the token's `limit`, the smaller of the token's and the account's `remaining`, and `resetSec`, or a refusal naming the cap that refused, `retryAfterSec`, and `strike` when that refusal completed a strike) come from `src/lib/userApi/rateLimit.ts`; `UserApiStrikeOutcome` (a suspension with its end, or a revocation with whether an account block was applied and its end, plus the committed `eventId`) from `src/lib/userApi/abuse.ts`. `UserApiEndpoint` (the `/api/v1/<endpoint>` path segments) and `UserApiRequestOutcome` (`'ok'|'not_modified'|'rate_limited'|'unauthorized'|'forbidden'`) label `user_api_requests_total`. `UserApiTokenInfo` is the `data` of `GET /api/v1/token` (the token's map, its granted and effective scopes, expiry, and the per-token and per-account caps with their window), built in `src/lib/userApi/handler.ts`. The read projections' wire DTOs (`src/lib/userApi/projection.ts`) are their own types, not derived from the in-app view models: `UserApiResource` (`'map'|'signatures'|'pilots'|'notes'|'mass_log'|'kills'`), `UserApiSystem` (a visible system; `id` is the `ap_map_system.id` connection endpoints name, `systemId` the EVE id; no intel notes), `UserApiConnection`, `UserApiMap` (`{ map: { id, name, scope, type, homeMapSystemId }, systems, connections }`), `UserApiSignature` (with its system's EVE id and name), `UserApiPilot` (a presence entry with no account id, character ids as strings), `UserApiNote`, `UserApiSystemNote` (one visible system's intel-notes text), `UserApiNotes` (`{ notes, systemNotes }`), `UserApiMassLogEntry` (one jump with its connection id and the EVE ids of both ends), `UserApiKill` (a cached kill in a visible system: killmail, system and victim ids, the SDE ship-type name, attacker count, and zKillboard's ISK estimate or null), `UserApiProjectionData` (resource to `data` type), `UserApiPayload<R>` (`{ data, hidden? }`, `hidden: true` only on a mass log withheld by Blackout) and `UserApiProjectionEntry<R>` (a cached resource: payload, `generatedAt`, serialised success `body`, weak `etag`, from `src/lib/userApi/cache.ts`). The Map Settings API tab (`src/app/(app)/actions/mapApi.ts`) reads `MapApiState` (the instance and map switches, the map's scopes, whether the viewer holds `api_manage`, the viewer's `UserApiAccountBlock` (`{ reason, until }`, `until` null when indefinite), the account's own tokens on the map, every token on it for an `api_manage` holder, and the token caps with the account's live count), whose lists are `UserApiTokenListItem` rows (the token's map id and name, label, prefix, scopes, the owner's current main name, whether the viewer's account owns it, dates, request count, and a computed `UserApiTokenStatus`: `'active'|'suspended'|'expired'|'map_deleted'|'api_disabled'|'lost_access'|'blocked'`; never the token or its hash). The Account Settings API tokens section reads `AccountApiState` (the instance switch, the account's block, and every non-revoked token the account owns on any map).

SDE self-refresh adds `ApSdeState` / `NewApSdeState` row types (the `ap_sde_state` singleton, `src/db/schema/ap/sde_state.ts`) — which SDE build the database holds and how the refresh job is going.

Derived-authority (permissions multi-tenant, stage 1) adds `ApAlliance` / `NewApAlliance` row types (the `ap_alliance` executor-corp cache). `ApCharacter` gains the `isDirector` boolean. Both back the `canManageMap` / `canCreateMap` gates in `src/lib/auth/rights.ts`.

map-layout-builder adds the free-form map dashboard types (directly defined): `PanelId` (the 12 draggable cards), `Breakpoint` (`'lg'|'md'|'sm'`), `PanelGroup` (`{ id: string; members: PanelId[]; active: PanelId }` — a grid cell's ordered tab members and active tab; a singleton is an untabbed panel whose `id` is its member's `PanelId`), and `MapLayoutConfig` (`{ version; layouts: Record<Breakpoint, Layout>; groups: Record<Breakpoint, PanelGroup[]>; hidden: PanelId[] }`). Grouping is per-breakpoint, parallel to `layouts`; a `layouts[bp]` item's `i` is a group id. `StoredMapLayout` is the pre-normalisation read shape (`groups` optional) that `migrateLayout` upgrades to a full `MapLayoutConfig`. `Layout` is `react-grid-layout`'s `readonly LayoutItem[]`, imported type-only (erased; safe in this server-imported barrel). Item `i`, group id, and member/active ids are structurally loose — the `PanelId` constraint is enforced at the Zod boundary (`src/lib/map/layout/schema.ts`) and in `DEFAULT_MAP_LAYOUT` (`src/lib/map/layout/panels.ts`), not the structural type. Stored on `ap_user.map_layout`.

The in-map audit console re-exports the view-models + query contract from `src/lib/map/audit.ts`: `AuditEventCategory` (`'system'|'connection'|'signature'|'note'|'map'|'access'`), `AuditEventRow` (one rendered commit — id/occurredAt/kind/category/actor + human `summary`/`destructive`), `AuditActor` (a distinct actor for the filter dropdown, with account-main rollup), `ActorSummary` (per-category counts + destructive total for the drill-down header), `AuditQueryParams` (the API/query filter shape), and `AuditPage` (`{ rows, nextCursor }`).

Per-title feature delegation (R4) adds the directly-defined view-model backing the Roles & Permissions tab: `DelegationRole` (`{ roleId, label, capabilities: MapCapability[] }` — one corp title and the capabilities delegated to it on a map; `view` is implicit and never listed) and `MapDelegationState` (`{ available: false } | { available: true; roles: DelegationRole[] }` — `available` is false on non-corp maps in v1). Produced by `src/app/(app)/actions/mapRoles.ts`.

routes-module adds `ApRouteDestination` / `NewApRouteDestination` row types, the enum unions `RouteSafety` (`shortest`/`safer`/`less_safe`) and `WhJumpMass` (`s`/`m`/`l`/`xl`), and the directly-defined planner domain types: `RoutePrefs` (per-account settings resolved from `ap_user`), `RouteHop` (one system on a route; `via` = how it was entered, with `connectionId`/`onMap`/`tag`/`viaSigId` — the departure-side sig code of the wormhole flown, null on every other hop kind), `RoutePlan` (`{ destinationSystemId, destinationName, reachable, jumps, hops }`), and `RouteDestinationView` (a saved destination joined to its system display fields). Computed by `src/lib/map/routePlanner.ts`, rendered by `RoutePlannerModule`.

Route **segmentation** types group that flat hop list into navigational instructions: `RouteSpaceKind` (`kspace`/`jspace`/`pochven`/`abyssal`/`unknown`), `RouteSegmentPoint` (a segment end resolved for display — `label` is the map tag when set, else the system name), and `RouteSegment` (`kind` one of `origin_only`/`gate_run`/`chain_run`/`wh_jump`/`wh_transit`/`jumpbridge`/`eve_scout`/`eve_scout_transit`, plus the inclusive `fromHopIndex`/`toHopIndex` range it covers, `jumps`, `through`, `entrySigId`/`exitSigId`, `direction`). Consecutive segments share a boundary index and together tile the whole hop list. `RouteInstructionToken` is one fragment of a rendered instruction (`text` / `system` / `sig`), letting the UI colour systems and set sig codes in mono while the clipboard form concatenates the `text`. All derived by `src/lib/map/routeSegments.ts`.

Observability (Phase 1) adds the health-probe types (directly defined): `HealthComponentStatus` (`'ok'|'degraded'|'down'|'unknown'`), `HealthComponentName` (`'db'|'realtimeBus'|'worker'|'esi'|'migrations'`), `HealthComponent` (`{ status, detail? }`), and `HealthReport` (`{ status, checkedAt, components }`). Produced by `src/lib/health/probe.ts`, served by `GET /api/health/ready`. The route returns 503 iff `HealthReport.status` is `down`.

Observability (Phase 2) adds the metrics types (directly defined): `MetricLabels` (`Record<string,string>`), `EsiMetricOutcome` (`'success'|'http_error'|'decode_error'|'breaker_open'|'downtime'|'rate_limited'|'token_error'`), `CounterSnapshot` / `HistogramSnapshot` (one metric's name/help + per-label-set series; histogram buckets are cumulative `le` bounds), `MetricsSnapshot` (`{ counters, histograms }`), and `GaugeReadings` (instantaneous gauges: tracked characters, visible systems, session WS connections, public spectator WS connections, open ESI breakers, job backlog/abandoned, db pool total/idle/waiting, process memory + event-loop lag, live and suspended user API tokens, plus `tableRows: TableRowEstimate[]` — per-`ap_*`/`universe_*`-table row estimates rendered as `db_table_rows{table}`). `TableRowEstimate` is `{ table, rows }`. Produced by `src/lib/metrics/registry.ts` (cumulative) and `src/lib/metrics/gauges.ts` (instantaneous); PII-free by construction.

Observability (Phase 8) adds the deepened-instrumentation outcome label types (directly defined, all bounded string-literal unions so call-site labels stay typed and low-cardinality): `JobOutcome` (`'success'|'failure'` — `job_runs_total`), `LocationPollOutcome` (the `PollNotes` stop reasons plus `online`/`offline`/`esi-outage` — `location_polls_total`), `WebhookOutcome` (`'success'|'rate_limited'|'http_4xx'|'http_5xx'|'network_error'` — `webhook_deliveries_total`), `TokenRefreshOutcome` (`'success'|'missing_token'|'invalid_grant'|'network_error'|'http_error'|'invalid_response'` — `esi_token_refresh_total`), `JwkRefreshOutcome` (`'success'|'error'` — `jwk_cache_refresh_total`), and `PublicWsUpgradeOutcome` (`'accepted'|'rate_limited'|'unauthorized'|'at_cap'` — `public_ws_upgrades_total`).

Observability (Phase 6) adds the instance-alerting types (directly defined, no DB-derived rows — alert state is in-memory): `AlertRuleKey` (`'db'|'worker'|'esi_breakers'|'job_abandoned'|'error_rate'`), `AlertRuleStatus` (`'ok'|'degraded'|'down'|'unknown'`; `unknown` is a no-op so a DB-backed rule can't false-resolve during a DB outage), `AlertSignals` (one gather of every signal — DB-probe latency, worker staleness, open breakers, abandoned jobs, recent errors — each nullable when unreachable), `AlertRuleResult` (`{ key, status, detail }`), and `AlertTransition` (`{ key, kind: 'fire'|'resolve', status, detail, firingSince }`). Consumed by `src/lib/alerts/rules.ts` (pure rules + dedup state machine) and `src/lib/alerts/scheduler.ts` (the loop, booted from `server.ts`); PII-free by construction.

Public map share adds `ApMapShare` / `NewApMapShare` row types, the enum union `SharePresenceMode` (`none`/`anonymous`/`full`, the `share_presence_mode` pgEnum), and the directly-defined `ShareRedactionProfile` (`{ presenceMode, showSignatures, showConnectionSigIds, showBubbles }`) — the per-token flag set `resolveShareToken` (`src/lib/map/share.ts`) resolves and the public projection branches on. Two management-side shapes ride alongside it: `MapShareListItem` (`ShareRedactionProfile & { id, token, label, expiresAt, expired, createdAt, createdByName }`) is one row of the Share links panel and carries the raw token for the copy-link button, so it is only ever returned to a viewer holding `share_manage`; `LiveShareBadge` (`{ id, label, expiresAt }`) is the token-free feed for the in-map indicator every viewer of the map sees.

Per-map user API adds `ApMapApiToken` / `NewApMapApiToken` row types and the enum unions `ApiScope` (`map`/`signatures`/`pilots`/`notes`/`mass_log`/`kills`, the `api_scope` pgEnum) and `ApiTokenRevokeReason` (`creator`/`manager`/`abuse`/`admin`).

Redacted public-share view-model types (shaped in `src/lib/map/loadPublicMap.ts`): `PublicMapSystemNode`, `PublicMapConnectionEdge`, `PublicMapSignature`, `PublicPresenceSystemCount`, `PublicPresencePilot`, `PublicMapPresence`, `PublicMapViewData`. Distinct types from their `loadMap.ts` counterparts, not `Omit`/`Partial` derivations — they have no field capable of carrying an intel note, a map note, structure intel, an audit entry, or per-row attribution. `PublicMapEntrance` and `PublicMapEntranceHop` (shaped in `src/lib/map/publicEntrances.ts`) are the k-space ways into the chain and the per-jump wormhole path from one to the map's Home.
