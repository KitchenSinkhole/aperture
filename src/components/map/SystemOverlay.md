## SystemOverlay

**Purpose:** Floating overlay panel showing the active character's current system, a search/D-Scan box over the other pilots in it and their ships, the non-abyssal connections out with mass/EOL state, and Ping/Rally action buttons for the current node.
**File:** `src/components/map/SystemOverlay.tsx`

### Also exports
- `matchDscanRow(row: ParsedDscanRow, roster: readonly MapPresenceEntry[]): MapPresenceEntry | null` — the roster entry a D-Scan line names, or null when nobody in the list flies it.
- `resolveDscan(rows, roster, shown): { unmatched, scannedHullByChar }` — resolves a scan's ship rows against the roster, each row consuming the pilot it resolves to (a second row on the same pilot comes back unmatched; two friendlies sharing a hull name each take a row); `scannedHullByChar` maps each resolved pilot in `shown` to the hull type the scan listed them in.
- `orderPilots(others, needle, scannedHullByChar, sort): MapPresenceEntry[]` — the pilot table's row order: the pilots `scannedHullByChar` lists in the hull they currently fly, then query hits, then the rest, the column `sort` ordering within each tier. `PilotSort` / `PilotSortKey` are exported for it.
- `Highlight({ text, needle })` — `text` with every case-insensitive occurrence of `needle` `<mark>`ed.

### Props

| Prop | Type | Required | Description |
|---|---|---|---|
| viewData | MapViewData | yes | The live map snapshot the canvas already maintains (systems + connections). Provides `map.id` used by the Ping and Rally API calls. |

### Renders
A compact, low-chrome vertical panel tuned to be as tight as possible (it lives in a Document PiP window that steals screen space from the game client): a single class+tag+name header line, a search box (a `Clear D-SCAN` button at its right while there is something to clear, and a notice line beneath it when there is something to say), a self-excluding pilots table with any D-Scanned enemy rows pinned on top and the D-Scanned friendlies on green rows just below them, and a connections list of thin rows. The section labels ("Pilots in system" / "Connections") are intentionally **omitted** — the colour mass dot on each connection row and a hairline top border are the only separators. No interactivity, no tooltips (synthetic events don't cross the PiP document).

### Behaviour & Interactions
- Reads `useMapActiveChar()` for `activeCharId` / `activeCharSystemId` and `usePresenceForSystem(activeCharSystemId)` for the in-system roster — so it re-renders live off the presence store's `characterUpdate` folding with no extra wiring.
- **Header:** resolves the `MapSystemNode` where `systemId === activeCharSystemId`; a single baseline row — class (coloured via `systemClassColor(node.security)`) + tag + the muted name/alias inline (no longer a separate line). Class+tag lead because the system name is already visible in-game.
- **Ping button** (right-aligned in header): fires `pingSystemOnServer({ mapId, mapSystemId: node.id })` on click; disabled when no node is on the map or a request is in flight. Border colour `#38bdf8` matches `UNDERGLOW_PRESETS.ping.color`.
- **Rally button** (right-aligned in header, next to Ping): toggles `ap_map_system.rally_at` via `updateSystemOnServer` — sets to the current ISO timestamp when unset, clears to null when already set. Border colour `#9036e4` matches `RALLY_UNDERGLOW.color`. Disabled when no node or request is in flight. **Easter egg:** shift-clicking while *setting* (not clearing) a rally point plays `/sounds/rally.mp3` via the Web Audio API.
- **Off-map fallback:** when the active char's system has no placed node, the header falls back to a roster entry's `systemSecurity` / `systemTrueSec` / `systemName`; no tag, and the connections section is hidden.
- **No located character** (`activeCharSystemId == null`): renders a neutral "No tracked character located" placeholder.
- **Pilots:** roster filtered to `characterId !== activeCharId`; rendered as a compact `table-fixed` table (Pilot | Name | ship-class icon | Type, the icon column narrow and unlabelled under a "Type" header spanning both). Column headers are sortable (asc/desc toggle with chevron indicator); default sort is Type asc. Blank custom-ship-name values always sink to the bottom regardless of direction. Pinned enemy rows from a D-Scan paste lead the table, above the pilots and outside the column sort; the pilots that paste resolved come next, and the column sort orders within them. A row the last scan resolved has a dark green background for as long as the pilot still flies the hull the scan listed — a reship drops the row back into the plain list; a query hit is `<mark>`ed in its cells only. Empty state: "Alone in system" text (no table rendered) — only when there are no pilots **and** no pinned enemy rows.
- **Search / D-Scan** (between the header and the pilot table, placeholder `Search or paste D-SCAN`, always rendered — a pilot alone in system still has a box to paste a scan into):
  - **Typed query:** live (per-keystroke) case-insensitive substring match over pilot name / ship name / hull type on the same self-excluding roster the table shows. Matching pilots are lifted above the unmatched ones, below any D-Scanned friendlies — the active column sort still orders within each tier — with every occurrence of the query `<mark>`ed in their pilot, ship-name and type cells, so the cell that produced the hit is visible at a glance. Pinned enemy rows are searched on the same keystroke over their D-Scan ship name and type — not the literal `Unknown pilot` cell, which holds no scanned text — and mark their hits the same way, though they hold scan order instead of being lifted. `"<query>" not found` renders under the box only when neither a pilot **nor** an enemy row matches, the echoed query cut to `QUERY_ECHO_MAX` characters with an ellipsis so a long one can't wrap the line. Clearing the box restores the plain list.
  - **Paste:** clipboard text that `parseDscanPaste` accepts as at least one D-Scan row is intercepted (`preventDefault`, box cleared before anything is awaited) and never falls through to a text search — including a scan of nothing but structures, which renders a `No ships in D-SCAN` notice under the box (cleared by typing or after `NOTICE_TTL_MS`, 30s) rather than being searched as text. The scanned type ids are then classified against the SDE by `fetchScanTypes`, and rows are narrowed to ships, dropping everything else a scan lists. Classification is the SDE's `Ship` category, so capsules count as ships. **A type id the SDE does not carry is kept, not dropped** — a hull newer than the ingested SDE arrives that way, and it pins as an enemy with an empty icon cell rather than vanishing from an intel panel. When the classification itself fails (already toasted, but toasts render in the opener document behind the game client) the panel shows a `Ship list unavailable, D-SCAN not read` notice and leaves the pinned set untouched, so a failed read is never presented as a clean scan. The per-line match below reads the **full** in-system roster including the active character, not the self-excluding list the table shows — a scan pasted from one tracked alt's client lists the other's hull, and a pilot the match roster omits resolves as an enemy; only pilots the table shows are recorded as scanned, so a scan of nothing but the active character's own hull leaves no result. Each line consumes the pilot it resolves to: a second line on the same pilot pins as an enemy, and two friendlies sharing a hull name each take a line. Each paste claims a scan number synchronously, before the await, and a paste overtaken by a later one discards its result: the newest scan is the set on screen whatever order the awaits settle in. Each surviving line resolves to the roster entry on the same `shipTypeId` plus, in order, an exact ship-name match on `shipNameKey` of both sides (trimmed, whitespace runs collapsed, case folded), else the client's `<Pilot>'s <Type>` default anchored at the start of the name cell — anchored so a pilot whose name prefixes another's can't claim their ship, and an ambiguous prefix resolves to nobody rather than to whoever the roster lists first. A matched line lifts its pilot's row to just below the enemy rows on the green background (the pilot already sits in the table), for as long as they fly the scanned hull; unmatched ones are pinned atop the pilot table as **enemy rows** entirely in shades of red — `Unknown pilot` in the Pilot column, then the D-Scan ship name and type — plus the hull icon `resolveShipClass` gives for the type id and its classified group (icon cell left empty when that resolves to null). Scan order is preserved.
  - Enemy rows and the green friendlies have **no timer** and resolve against the roster as it stood at paste time — presence churn doesn't re-resolve them. They stay until the next D-Scan paste replaces the result (a scan is a full snapshot of what's in range, so an all-friendly scan clears the enemy rows), the `Clear D-SCAN` button — shown at the right of the search box only while a result is held — drops it and discards any paste still awaiting its lookup, or the active character's system changes. The section is keyed on `activeCharSystemId`, so a jump discards the result along with the typed query: a scan describes what is in range of the one system it was taken in.
- **Connections:** `viewData.connections` incident to the current node and `scope !== 'abyssal'`; each row is `[mass dot] [sig] [class] [tag] [far name] [badges] [EOL countdown]`. The mass dot is coloured by `connectionStyle(edge).stroke` (mass status for WH, scope colour otherwise); the **sig** is the 3-char `sigId` of the in-system signature that resolves to this connection (`viewData.signatures` filtered to `mapSystemId === node.id && mapConnectionId === edge.id` — the sig as seen on *this* scanner, not the far side; `.slice(0, 3)` defensively), muted/mono, between the dot and the class; the far-end node gives the class colour + tag/name; `connectionBadges` minus the EOL badge (STATIC / size); a live EOL countdown when `eolStage !== 'none'`. The section has a hairline top border instead of a label; no heading.

### Local State
- `useEolCountdown(edge)` — per-connection-row hook ticking a `now` clock every 30s while the edge is EOL; returns a formatted "time left" string for `eol`/`critical`, an `"expired 3h ago"` elapsed string for the manual `expired` stage, or null.
- `pinging: boolean` (Header) — true while a ping POST is in flight; disables the Ping button.
- `togglingRally: boolean` (Header) — true while a rally PATCH is in flight; disables the Rally button.
- `sort: PilotSort` (Pilots) — `{ key: PilotSortKey; dir: 'asc' | 'desc' }` tracking the active pilot table sort column and direction.
- `query: string` (PilotSection) — the search box's text, matched live with no debounce; a D-Scan paste leaves it empty.
- `dscan: DscanResult | null` (PilotSection) — the last D-Scan paste's result: `enemies` (`{ key, name, typeName, shipClass }` rows pinned atop the pilot table) and `scannedHullByChar` (each shown pilot the scan resolved, mapped to the hull type it listed them in; their rows lift and turn green while they still fly it). Null when nothing was pinned or resolved. Replaced by each paste with ships, dropped by the Clear button, discarded with the section on a system change.
- `notice: { text: string } | null` (PilotSection) — the D-SCAN outcome line under the box (`No ships in D-SCAN`, or the unavailable-ship-list notice); cleared by typing or after `NOTICE_TTL_MS`. Each showing is a fresh object, so a second all-structures scan restarts the TTL rather than riding out the first timer.
